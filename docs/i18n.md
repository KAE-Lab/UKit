# Internationalisation

UKit est traduit en **français, anglais et espagnol**. Aucune chaîne visible par l'utilisateur ne doit
être écrite en dur dans un composant.

Implémentation : [`src/shared/i18n/`](../src/shared/i18n/) — `Translator.ts` et les trois
dictionnaires `fr.ts`, `en.ts`, `es.ts`.

## Utilisation

```tsx
import Translator from '../../shared/i18n/Translator';

<Text>{Translator.get('LIBRARIES')}</Text>
<Text>{Translator.get('HIDDEN_RESULT', nombreCache)}</Text>
```

`Translator` est un singleton : pas de hook, pas de contexte, pas de provider. Il est directement
importable depuis n'importe quel fichier, y compris hors composant.

### Substitution

Le marqueur d'interpolation est `$-`, remplacé positionnellement par les arguments passés après la
clé :

```ts
ADD_TO_CALENDAR_DESCRIPTION: 'Voulez vous ajouter l\'événement "$-" au calendrier ?'
Translator.get('ADD_TO_CALENDAR_DESCRIPTION', 'Algorithmique')
// → Voulez vous ajouter l'événement "Algorithmique" au calendrier ?
```

Les arguments manquants sont remplacés par une chaîne vide, jamais par `undefined`.

### Comportement si la clé est absente

`Translator.get` **renvoie la clé elle-même**. C'est un choix qui évite un écran vide, mais qui rend
un oubli visible en production sous la forme d'un libellé en majuscules (`NO_RESULTS`). Voir les
limites.

## Les dictionnaires

Les trois fichiers contiennent aujourd'hui **215 clés, strictement identiques d'un dictionnaire à
l'autre**. Cette parité est ce qui rend le typage utile :

```ts
export type TranslationDict = typeof EN;      // en.ts est la référence
export type TranslationKey = keyof TranslationDict;
```

`en.ts` est déclaré sans annotation de type : c'est lui qui **définit** le contrat. `fr.ts` et `es.ts`
sont annotés `TranslationDict`, donc le compilateur refuse une clé manquante ou surnuméraire dans ces
deux fichiers. Ajouter une clé se fait donc **toujours dans `en.ts` en premier**, sinon les deux
autres fichiers deviennent invalides.

## Langue active

`TranslatorService` maintient une langue courante, initialisée depuis
`SettingsManager.getLanguage()` et mise à jour par abonnement :

```ts
SettingsManager.on('language', (newLang) => Translator.setLanguage(newLang));
```

`setLanguage` fait deux choses : il fixe la langue du dictionnaire, et il appelle `moment.locale()`.
Les dates affichées dans l'application suivent donc la langue choisie, sans code supplémentaire. Une
langue inconnue retombe sur l'anglais.

Détermination initiale de la langue :

- `languageFromDevice()` ([`AppCore.tsx`](../src/shared/services/AppCore.tsx)) lit la locale système
  (`SettingsManager.settings.AppleLocale` sur iOS, `I18nManager.localeIdentifier` sur Android) et la
  réduit à `fr`, `es` ou `en`.
- L'[onboarding](features/onboarding.md) applique ce résultat par défaut, et laisse l'utilisateur le
  changer à l'étape 2.
- Le réglage reste modifiable à tout moment depuis [Réglages](features/settings.md).

### Semaine commençant le lundi

`Translator.ts` redéfinit la locale anglaise de moment au chargement :

```ts
moment.updateLocale('en', { week: { dow: 1, doy: 4 } });
```

Sans cela, l'anglais ferait commencer la semaine le dimanche, ce qui désaligne les vues hebdomadaires
du planning et les numéros de semaine ISO utilisés par Celcat. **Ne pas retirer cette redéfinition.**

## Ajouter une chaîne

1. Ajouter la clé dans [`en.ts`](../src/shared/i18n/en.ts) — c'est la source du type.
2. Ajouter la même clé dans [`fr.ts`](../src/shared/i18n/fr.ts) et
   [`es.ts`](../src/shared/i18n/es.ts). Le compilateur signale l'oubli.
3. Utiliser `Translator.get('MA_CLE')` **sans transtypage**. Si TypeScript refuse la clé, c'est
   qu'elle manque dans `en.ts` : c'est le garde-fou qui fonctionne, pas un obstacle à contourner.

Conventions de nommage : SCREAMING_SNAKE_CASE, préfixe par domaine quand c'est utile
(`BU_OPEN`, `CROUS_MARKET`, `BIOMETRY_PROMPT`), et clé descriptive du sens plutôt que du texte
français.

## Vérifier

- Basculer la langue dans Réglages et parcourir les quatre onglets : aucun libellé en majuscules
  brutes, aucune chaîne restée en français.
- Vérifier les dates : elles doivent suivre la langue (mois, jours, format).
- Vérifier les écrans à état vide et les modales, souvent oubliés.

## Limites connues

- **Treize clés sont invoquées avec un transtypage et ne sont définies nulle part.** Le motif
  `Translator.get('X' as Parameters<typeof Translator.get>[0])` contourne la vérification de type ;
  comme `get` renvoie la clé absente telle quelle, ces libellés s'affichent en majuscules brutes dans
  l'interface. Les clés concernées sont `ALL_ESTABLISHMENTS`, `RESTO_U`, `CROUS_MARKET`,
  `SEARCH_RESTO_CITY`, `ALL_LIBRARIES`, `OPEN_LIBRARIES`, `SEARCH_BU_CITY`, `SEARCH_BUILDING`,
  `NO_BUILDING_FOUND`, `NO_FREE_ROOMS`, `NO_RESULTS`, `NO_RESULTS_FOUND`, `ROOMS`. Elles vivent dans
  les écrans de liste Campus ([features/campus.md](features/campus.md)).
- **Les replis `|| 'texte'` accompagnant ces appels ne se déclenchent jamais** : `get` renvoie une
  chaîne non vide (la clé), qui est donc toujours retenue par l'opérateur.
- **Le motif `Translator.get(x) || 'texte français'` est répandu** ailleurs aussi, y compris sur des
  clés existantes. Il est inoffensif mais trompeur : il donne l'impression d'un repli qui n'a jamais
  lieu.
- **56 clés définies ne sont utilisées par aucun appel littéral.** Une partie est appelée
  dynamiquement (jours de la semaine, listes de thèmes et de langues de l'onboarding), le reste est
  du vocabulaire hérité.
- **Certaines chaînes restent en dur**, en français, hors du système de traduction : les noms de
  jours et de mois de [`GreetingBlock.tsx`](../src/features/Scolarite/components/GreetingBlock.tsx),
  les messages de [`Alerts.ts`](../src/shared/ui/Alerts.ts), le retour visuel de test de
  [`NotificationService.ts`](../src/shared/services/NotificationService.ts), et les titres de
  notification de cours.
